## Agreed product boundary

- Public Feed containing the newest 50 Posts in reverse chronological order.
- Clerk sign-in; authenticated Members can publish and like Posts.
- Posts are exactly one of a Standalone Post, Reply, Quote Post, or Repost. Standalone Posts and Replies contain 1–280 trimmed characters; Quote commentary is optional, with empty commentary producing a Repost. Authors can delete, but not edit, their Posts.
- Public, read-only Profiles use Clerk-projected display names and avatars and list the Member's Posts.
- The Feed contains Standalone Posts, Quote Posts, and Reposts but excludes Replies. Profiles contain every authored kind with relationship context.
- Replies form bounded, flat Conversations on `/posts/[postId]`; Replies may address any active non-Repost Post, including another Reply, while engagement shown on a Repost always targets its ultimate source.
- Quote Posts show one live, shallow referenced-Post preview. Reposts carry no independent engagement, are unique per Member and ultimate source, and are reversible.
- New Posts, Replies, Quote Posts, Reposts, deletion states, relationship counts, and Like counts update reactively across browser sessions.
- No following, personalized feeds, media, search, notifications, reporting, blocking, audience controls, moderation tooling, bookmarks, direct messages, profile editing, pagination, or infinite scrolling.

## Agreed technical shape

- Use Clerk development credentials and describe the deployment as a preview.
- Use npm with a committed lockfile, select Node `24.x` on Vercel, and align `.node-version` with the tested local Node 24 patch.
- Import the public GitHub repository into Vercel. Override its build command with `npx convex deploy --cmd-url-env-var-name NEXT_PUBLIC_CONVEX_URL --cmd "npm run build"` so every successful deployment builds Next.js against and deploys the selected Convex backend.
- Keep the production `CONVEX_DEPLOY_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, and `CLERK_SECRET_KEY` in Vercel's Production environment. Keep `CLERK_JWT_ISSUER_DOMAIN` in the production Convex deployment. Commit an `.env.example`, ignore real environment files, and keep secrets out of diagnostics.
- Treat issue #2 as a hard deployment gate: the public Vercel URL must prove Clerk sign-in/sign-out and a real Convex query before any product feature ticket starts.
- Project authenticated Clerk identity into Convex with an idempotent client-triggered mutation. A Clerk webhook is a production follow-up.
- Use `members`, `posts`, and `likes` tables. Give every Post a required kind, migrate existing Posts to `standalone`, and model Reply parents and Conversation roots explicitly. Normalize every action whose target is a Repost to that Repost's ultimate source, but otherwise retain a Quote Post's direct reference so quoting a Reply or Quote Post preserves the selected context. Maintain active direct Reply and active Repost counts transactionally. Enforce authorization, ownership, uniqueness, validation, counters, and cascading Like deletion inside Convex mutations.
- Expose cohesive `Members` (`ensureCurrent`, `getProfile`) and `Posts` (`listFeed`, `listByMember`, `getConversation`, `create`, `createReply`, `createQuote`, `toggleRepost`, `remove`, `toggleLike`) modules. Keep their registered Convex files as thin validated handlers over deep plain-TypeScript modules under `convex/model`; pass the existing Convex context directly so each workflow stays in one transaction. Keep Like and Repost persistence internal to `Posts`; add no repository or speculative adapter layer.
- Reserve the `convex/` root for the public API surface and deployment configuration: one registered module per vertical (`members.ts`, `posts.ts`, `status.ts`) beside `schema.ts`, `auth.config.ts`, and `convex.config.ts`. Keep everything else in `convex/contract` (client-safe validators and their derived types), `convex/lib` (shared pure code), `convex/model` (server-only workflow modules), and `convex/tests`. Convex derives every API path from the file path — `api.posts.listFeed` requires `convex/posts.ts` — so the registered modules cannot move into a subdirectory; listing the root is how a reader finds the whole contract.
- Declare each endpoint's argument and return shape once as a validator in `convex/contract` and derive its TypeScript type with `Infer`. Registered modules reference those validators and delegate to `convex/model`, so no outcome shape is written twice.
- Return complete immutable, discriminated Post display models rather than raw records. Include author details, Like and relationship counts, viewer Like/Repost state, permissions, relationship context, and at most one shallow referenced-Post preview; never recursively embed display models.
- Parse Post content into a refined value at the backend interface. Return precise tagged result values for expected failures; reserve throws for defects.
- Convert deleted Standalone Posts, Replies, and Quote Posts into author-free, content-free tombstones; delete their Likes and exclude them from Feed/Profile indexes and relationship counts. Hard-delete Repost wrappers. Reject new engagement against tombstones, while existing Quote Posts show “Quoted Post unavailable” and Conversations retain structural tombstones.
- Keep one active Repost per Member and ultimate source. Reposts are ordered by repost time and attributed to the reposter, while their shallow source display retains the source author and publication time.
- Keep the root layout and static shell as server components. Isolate the Convex provider and reactive product behavior in focused client components.
- Use `/` for the Feed, `/members/[memberId]` for Profiles, and `/posts/[postId]` for stable Conversation links. Opening a Reply link retains its URL while resolving and identifying the Conversation root and requested Reply.
- Use strict TypeScript with the additional safety flags required by `coding-standards`. Use direct imports and document every exported symbol.
- Keep dependencies narrow: Convex validators, a small local tagged `Result`, Clerk, Tailwind, Vitest, and `convex-test`. Add no ORM, global state library, generic repository, Effect, Zod, or component library unless the selected design creates a concrete need.
- Give coding agents version-aligned framework context without vendoring the Next.js or Convex repositories. Retain the Next.js-managed instructions in `AGENTS.md` so agents read the bundled documentation in `node_modules/next/dist/docs/`. After the application and local Convex dependency exist, run `npx convex ai-files install`; retain its generated guidelines and managed agent-file sections, and use `npx convex ai-files status` to detect stale guidance.

## Interaction contract

- Acknowledge every action immediately. A control enters a visible pending state at interaction start even when its data change is not optimistic.
- Optimistically update Like state and count, with rollback on failure.
- Optimistically update Repost state and count, with rollback on failure. Do not optimistically publish Replies or Quote Posts.
- Keep the Post composer content and deleted Post visible while their mutations are pending; disable duplicate submission and commit the visible change only on success.
- Show precise tagged failures inline with a clear retry path.
- Reply actions navigate to the Conversation page and focus a contextual composer. Quote actions open a focus-trapped dialog with a shallow target preview and optional commentary; trimmed-empty commentary creates a Repost. The Repost action toggles immediately, while submitting empty Quote commentary for an already-reposted source returns a precise `already-reposted` outcome instead of toggling it off.
- Keep Reply and Quote drafts only while their composer is mounted. Cancel discards the draft, failures preserve it, and a pending submission prevents closing. Request sign-in before opening a composer for a signed-out visitor, and return focus to the triggering control when the Quote dialog closes.
- Treat Post content as plain text: trim outer whitespace, preserve internal whitespace and line breaks, and rely on React escaping. Do not parse Markdown, links, mentions, or hashtags.
- Enable Next.js 16.3 Cache Components and Partial Prefetching with `cacheComponents: true` and `partialPrefetching: true`.
- Use prefetched static route shells, meaningful `loading.tsx` fallbacks, and default `<Link>` prefetching for navigation. Use `useLinkStatus` only as supplemental feedback when navigation can still block.
- Keep Convex Feed, Profile, and Conversation data uncached and reactive. Render local client-side skeletons while each `useQuery` subscription is pending because Partial Prerendering does not preload Convex data.

## Experience constraints

- Require semantic landmarks, keyboard operation, visible focus, labeled icon controls, sufficient contrast, reduced-motion support, and an accessible character counter.
- Use Next.js error boundaries, safe structured backend diagnostics, and explicit retry states. Add no analytics or third-party monitoring today.
- Use the supplied three-column shell at 1000px and wider, remove the context rail below 1000px, and use a sticky compact top bar below 800px.
- Use a text-only `Still` wordmark in the reading typeface. Add no separate logo asset.
- The desktop context rail contains one quiet “About Still” card describing the finite, live-updating Feed; it contains no trends, recommendations, rankings, or calls to action.
- Query 51 recent Posts, render at most 50, and use the extra result only to detect truncation. End the Feed with “You’re caught up” when complete or “Showing the latest 50 posts” when truncated.
- Query the latest 51 Replies across a Conversation, render at most 50 in chronological order, and use the extra result for “You’re caught up” or “Showing the latest 50 replies.” When a Reply URL targets an older item outside that window, always include and identify the requested Reply, then fill the remaining bounded result with the latest Replies and retain honest truncation copy.
- Present Conversations as a flat discussion. Replies to Replies show “Replying to …” context instead of nested indentation. Display active direct Reply counts and active Repost counts; deleted Replies do not contribute, and there is no Quote count or Quote collection.
- On a Repost card, Reply, Like, Quote, and Repost actions target the ultimate source; only “Remove Repost” targets the wrapper. Tombstones appear only where needed on Conversation pages, reveal no author or content, and expose no engagement controls.
- Use `Like` consistently in domain, code, tests, and interface copy. The selected state is `Liked`.
- Use the accessible Muted token `#6B726C`; reserve Danger `#9B3B3B` and Danger soft `#F5E9E7` for destructive and error feedback.
